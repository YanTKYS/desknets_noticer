# desknet's noticer

desknet's NEOの「電子会議室」にある任意のトピックへの新規投稿を検知し、
**通知を希望する利用者にだけ** Chromeのデスクトップ通知を表示する非公式の
Chrome拡張機能です。

> **本ツールはdesknet's NEOの提供元（株式会社ネオジャパン等）とは無関係の非公式ツールです。**
> desknet's NEOの公式ロゴ・商標は使用していません。

- 対応対象: **desknet's NEO v6.0 R1.0**（電子会議室の新着情報画面）
- 実装形態: Google Chrome拡張機能（Manifest V3、ビルド不要）
- 通知の仕組み: 全利用者への一斉通知ではなく、**この拡張機能を導入し、対象トピックの
  通知を明示的に有効化した利用者だけ**が通知を受け取ります。

バージョンごとの変更点は [CHANGELOG.md](CHANGELOG.md) を参照してください。

## できること

- 電子会議室の「新着情報」画面を数分間隔で確認し、設定で有効化した対象トピックへの
  新規投稿だけをデスクトップ通知します。
- 通知対象トピックは、利用者が**最大20件**まで自由に追加・削除・編集できます。
- 各トピックは「トピック名」と「トピックURL」で登録します。URLから会議室ID（`fid`）と
  トピックID（`tid`）を読み取り、新着照合はこの内部IDを優先して行うため、トピック名を
  後から変更しても同じトピックとして継続検知できます。
- 監視対象が何件になっても、desknet's NEOへの通信は新着情報画面の**1回の取得だけ**です
  （トピックごとに個別アクセスすることはありません）。
- 初回確認時点で存在する投稿は通知しません（基準値として登録するのみ）。
- 同じ投稿を重複して通知しません。
- 投稿・既読化・更新・削除など、desknet's NEO側の状態を変更する操作は一切行いません。
- 「電子会議室を開く」ボタンおよび通知クリックで、設定した新着情報画面へ遷移します。
- 設定画面の「テスト通知を送信」で、desknet's NEOへアクセスせずに端末の通知機能
  そのものが使えるかを確認できます。
- デスクトップ通知が使えない端末でも、ツールバーアイコンのバッジとポップアップで
  新着件数を確認できます。

## インストール

詳細手順は [docs/installation.md](docs/installation.md) を参照してください。概要は次のとおりです。

1. `chrome://extensions` を開き、「デベロッパー モード」をオンにする。
2. 「パッケージ化されていない拡張機能を読み込む」からこのリポジトリのフォルダを選択する。
3. Chromeでdesknet's NEOに通常どおりログインする（拡張機能にID・パスワードは入力しません）。
4. 拡張機能の設定画面で接続先URLと通知対象トピックを設定する。

## 設定の保存方法

設定画面には、目的に応じて3種類の保存操作があります。

| 操作 | 保存される内容 |
| --- | --- |
| 「接続先を保存」（接続確認の右側） | 電子会議室の新着情報画面URLだけ |
| 「このトピックを保存」（各トピックカードの削除ボタンの左側） | そのカード1件のトピック設定だけ |
| 「すべての設定を保存」（画面下部） | 接続先・全トピック・確認間隔・通知設定など、画面内のすべての変更 |

**「接続確認」を押しただけでは接続先は保存されません。** 接続確認は、入力したURLへ
実際に接続できるかを試すだけの操作です。保存するには「接続先を保存」を押してください。

未保存の変更がある項目には「未保存の変更があります」という文字表示（接続先欄の下、
および各トピックカード）が出ます。保存に成功すると消え、失敗した場合は未保存のまま
維持されます。

確認間隔・通知設定には個別の保存ボタンが無いため、画面下部の「すべての設定を保存」で
反映してください。

## 接続先URLの設定

設定画面（ポップアップの「設定」ボタン、または `chrome://extensions` の拡張機能詳細から
「拡張機能のオプション」）の「接続先」欄にURLを入力します。

> desknet's NEOのトップ画面URLではなく、
> 電子会議室の「新着情報」画面を開いた状態のURLを設定してください。

トップ画面やベースURLだけを登録しても新着情報を取得できません。ブラウザで電子会議室の
新着情報画面を開き、そのときのアドレスバーのURLをコピーして登録してください。

- `http` または `https` のURLのみ登録できます。前後の空白と末尾スラッシュの差異は
  自動的に正規化されます。
- 保存時に、そのURLのオリジンへのアクセス許可を求めるダイアログが表示されることが
  あります（他のサイトへはアクセスしません）。
- URLはソースコードに固定されておらず、利用者が設定したものだけを使用します。

## 監視対象トピックの設定

「通知対象トピック」の「＋ トピックを追加」ボタンで、通知対象を**最大20件**まで追加
できます。各カードの項目は、通知する（ON/OFF）・トピック名・トピックURL・解析された
会議室ID/トピックIDの表示（読み取り専用）・初回確認状態の表示・削除ボタンです。

**初期状態ではトピックは0件、追加したトピックも初期値は「通知する」がOFFです。**

### トピックURLの登録方法

自組織の電子会議室で対象トピックを開き、ブラウザのアドレスバーに表示されているURLを
そのまま「トピックURL」欄へ貼り付けてください。desknet's NEOはハッシュルーティング
（`#cmd=forumalist&fid=8&tid=2319&init=3` のような形式）を使用しており、このURLから
会議室ID（`fid`）とトピックID（`tid`）を自動的に読み取ります。

トピックURLは次を満たす必要があります。

- `http` または `https` の完全なURLであること
- 接続先に設定した新着情報画面と同一オリジンであること
- ハッシュ部分に `cmd=forumalist` と `fid`・`tid` が含まれていること

通知ONの場合はトピック名・URLの両方が必須です。同じ`fid`・`tid`の組み合わせを複数
登録することはできません（`fid`・`tid`が異なれば、同じトピック名は登録できます）。

### トピック名ではなく内部IDで識別する

新着投稿の判定は、**トピック名ではなく会議室ID（`fid`）とトピックID（`tid`）の
組み合わせを優先**して行います。そのため、後からトピック名を変更しても、URLが指す
会議室・トピックが変わっていなければ同一トピックとして継続検知します。トピック名は
表示用のラベルとしてのみ使います（`fid`・`tid`を取得できない旧設定に限り、トピック名の
完全一致で照合します）。

### 旧バージョン（v0.1.x）から更新した場合

v0.1.xの設定（固定2件・トピック名のみ）は、初回起動時に自動で新しい形式へ移行されます。
移行されたトピックにはURLが無いため、**安全のため自動的に「通知する」がOFFになります**。
設定画面の案内に従って該当トピックにトピックURLを入力し、必要に応じて「通知する」を
ONにして保存してください。

## 初回確認の扱い

トピックを初めて有効にしたときの最初の確認では、その時点で存在する投稿を「既知の投稿」
として登録するだけで、**通知は行いません**。以降の確認で新しく追加された投稿だけが
通知対象になります。

次の場合も「初回確認待ち」に戻り、その時点の投稿を通知せず基準値として登録し直します
（設定変更をきっかけに過去の投稿が大量通知されることはありません）。

- トピックURLを変更し、会議室ID（`fid`）またはトピックID（`tid`）が変わった場合
- OFFにしていたトピックを新たにONにした場合

トピック名だけを変更した場合（`fid`・`tid`が同じ場合）は、初回確認状態は維持されます。
設定画面には、各トピックについて「初回確認: 完了」「初回確認: 待ち」の表示があります。

## 確認間隔

- 選択できる間隔は **3分・5分・10分** の3種類です（初期値は5分）。
- `chrome.alarms` を使用しています。Chromeのアラームは厳密なリアルタイム実行を保証
  しないため、投稿から通知までの遅延が生じる場合があります。

## ログイン切れ時の動作

以下のような状態を検出した場合、**新規投稿として誤って通知することはありません**。

- ログイン画面へのリダイレクト
- 認証エラー・アクセス権限エラー
- セッション切れを示す画面
- 新着情報画面ではない想定外のHTML
- サーバーへ接続できない状態

これらの状態は、ポップアップ内の状態表示とツールバーアイコンのバッジで知らせます。
設定で「ログイン切れへ変化した最初の1回だけ通知する」をONにすると、正常状態から
ログイン切れへ変化した最初の1回だけデスクトップ通知します（初期値はOFFです）。

## 権限とプライバシー

権限ごとの理由、保存する情報・保存しない情報の詳細は
[docs/security.md](docs/security.md) を参照してください。要約:

- 使用する権限は `storage` / `alarms` / `notifications` / `offscreen` / `tabs` と、
  利用者が設定したオリジンのみを実行時に要求する `optional_host_permissions` です。
- 設定・通知済み履歴は `chrome.storage.local` にのみ保存します（Chrome同期は使いません）。
- desknet's NEOのID・パスワード、Cookie、投稿本文の全文は保存しません。
- desknet's NEO以外のいかなる外部サーバー・外部API・CDNとも通信せず、外部ライブラリも
  使用していません。

## トラブルシューティング

| 症状 | 確認事項・対処 |
| --- | --- |
| ポップアップが「未設定」のまま | 設定画面で接続先URLを登録し、保存してください。 |
| 「desknet's NEOへのログインが必要です」と表示される | ブラウザでdesknet's NEOに再ログインしてください。 |
| 「接続できません」と表示される | ネットワーク接続、URLの誤り、社内ネットワーク（VPN等）への接続状況を確認してください。「接続確認」ボタンで再試行できます。 |
| 「画面構造を認識できません」と表示される | desknet's NEOの画面が変更された可能性があります。開発者に連絡し、実画面のHTMLを確認してもらってください。 |
| 通知が来ない | 対象トピックがONになっているか、デスクトップ通知が有効か、Chrome自体の通知設定（OS側含む）を確認してください。初回確認直後は既存投稿が通知されない仕様です。設定画面の「テスト通知を送信」で、端末の通知表示自体が機能しているかを切り分けられます。 |
| テスト通知が「作成できませんでした」と表示される | 拡張機能を再読み込みしてください。それでも失敗する場合は、OS・Chromeの通知設定を確認してください。 |
| 「認識した投稿件数」が常に0件のまま | 接続先URLがトップ画面など「新着情報」画面以外を指していないか確認してください。設定画面の「詳細情報（デバッグ用）」で、トピックリンク検出件数・投稿行候補件数を確認できます。 |
| 対象トピックの投稿があるのに「対象一致」が0件のまま | トピックURLの`fid`・`tid`が正しく読み取れているか（カード内の表示）を確認してください。`fid`・`tid`が無い旧設定はトピック名の完全一致で照合するため、「詳細情報」の「設定トピック名がHTML内に存在」もあわせて確認してください。 |
| 同じ投稿が何度も通知される | 設定画面から通知済み履歴をリセットしていないかを確認してください。 |

## 既知の制限

- 新着情報画面は「投稿単位」ではなく「各トピックの最新状態」を一覧表示する方式です。
  そのため、**同一トピックへ短時間に複数投稿された場合、途中の投稿を個別に検知できず、
  最後の投稿しか通知されない可能性があります**。
- `chrome.alarms` による定期確認のため、**Chromeが起動していない間は確認されません。**
  Chromeを閉じている間の投稿は、次回起動後の確認で検知されます（同一トピックに複数の
  投稿があった場合は、上記のとおり最新の1件だけになります）。
- 「テスト通知を送信」で判定できるのは通知の**作成要求が成功したかまで**です。端末や
  OSの通知ポリシーによっては、作成に成功しても実際のバナー表示に至らない場合があります。
- 新着情報画面をGETで取得すること自体がdesknet's NEO側で既読扱いになるかどうかは
  未検証です（拡張機能から既読化APIを呼ぶことはありません。詳細は
  [docs/desknets-v6-dom-investigation.md](docs/desknets-v6-dom-investigation.md)）。

## アンインストール

`chrome://extensions` の拡張機能詳細から「削除」を選択してください。保存されていた
設定・通知済み履歴もあわせて削除されます。

## 開発者向け情報

### ディレクトリ構成

```text
desknets_noticer/
├─ manifest.json
├─ src/
│  ├─ background/        バックグラウンド処理（アラーム・通知・全体制御）
│  ├─ desknets/          desknet's NEOとの通信・DOM解析・認証状態判定
│  ├─ storage/           設定・通知済み履歴・実行時状態の永続化
│  ├─ popup/             ツールバーのポップアップUI
│  ├─ options/           設定画面UI
│  ├─ offscreen/         DOM解析専用のオフスクリーンドキュメント
│  └─ shared/            定数・データモデル・テキスト整形ユーティリティ
├─ tests/                解析処理などのテスト（Node.js + jsdom）
├─ docs/                 画面構造の仕様・インストール手順・セキュリティ方針
└─ icons/                独自作成のアイコン
```

### テストの実行方法

拡張機能本体はビルド不要ですが、テストの実行にはNode.jsが必要です
（`jsdom` を開発依存としてのみ使用しています）。

```sh
npm install
npm test
```

### 画面変更への対応

desknet's NEOの画面（HTML構造）が変更された場合、DOM解析が正しく動作しなくなります。
解析処理は `src/desknets/forum-parser.js` と `src/desknets/authentication-detector.js` に
集約しているため、この2ファイルを中心に調整してください。対象のDOM構造・セレクター・
識別キーの仕様は
[docs/desknets-v6-dom-investigation.md](docs/desknets-v6-dom-investigation.md) にまとめて
あります。

### デバッグ機能

設定画面の「詳細情報（デバッグ用）」から、最終取得日時・取得結果種別・トピックリンク
検出件数・投稿行候補件数・認識した投稿件数・対象トピック一致件数・新規判定件数・使用した
解析方式・設定トピック名がHTML内に存在したか・エラーコードを確認できます。投稿本文・
職員名・Cookie・認証情報は表示されません。

トピックリンクを1件も検出できなかった場合は、状態は「正常」のまま維持しつつ、エラー
コードに`NO_TOPIC_LINKS_FOUND`を記録します。新着が本当に0件なのか、画面変更でパーサーが
対象を認識できていないのかを切り分けるためです。
