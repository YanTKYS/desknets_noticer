# desknet's noticer

desknet's NEOの「電子会議室」にある任意のトピックへの新規投稿を検知し、
**通知を希望する利用者にだけ** Chromeのデスクトップ通知を表示する非公式の
Chrome拡張機能です。

> **本ツールはdesknet's NEOの提供元（株式会社ネオジャパン等）とは無関係の非公式ツールです。**
> desknet's NEOの公式ロゴ・商標は使用していません。

- 対応対象: **desknet's NEO v6.0 R1.0**（電子会議室の新着情報画面）
- 実装形態: Google Chrome拡張機能（**Manifest V3**）
- 通知の仕組み: 全利用者への一斉通知ではなく、**この拡張機能を導入し、対象トピックの
  通知を明示的に有効化した利用者だけ**が通知を受け取ります。
- 実機確認により判明したdesknet's NEO v6.0 R1.0の実際のDOM構造
  （`jforum-topiclink`等のCSSクラス、`data-fid`/`data-tid`属性、ハッシュルーティングの
  URL）に対応した専用パーサーを実装しています。詳細は
  [docs/desknets-v6-dom-investigation.md](docs/desknets-v6-dom-investigation.md) を
  参照してください。

## できること

- 電子会議室の「新着情報」画面を数分間隔で確認し、設定で有効化した対象トピックへの
  新規投稿だけをデスクトップ通知します。
- **通知対象トピックは、利用者が任意の件数（最大20件）を追加・削除・編集できます。**
  固定の2件だけに制限されていません。
- 各トピックは「トピック名」と「トピックURL」で登録します。URLから会議室ID（`fid`）と
  トピックID（`tid`）を読み取り、新着照合はトピック名だけでなくこの内部IDを優先して
  行うため、トピック名を後から変更しても同じトピックとして継続検知できます。
- 監視対象が何件になっても、desknet's NEOへの通信は新着情報画面の**1回の取得だけ**です
  （トピックごとに個別アクセスすることはありません）。
- 新着情報画面は「投稿単位」ではなく「各トピックの最新状態」を一覧表示する方式のため、
  同一トピックの最新の投稿者・投稿日時・投稿概要のいずれかが変化したことをもって
  新着と判定します。
- 初回確認時点で存在する投稿は通知しません（基準値として登録するのみ）。
- 同じ投稿を重複して通知しません。
- 投稿・既読化・更新・削除など、desknet's NEO側の状態を変更する操作は一切行いません。
- 「電子会議室を開く」ボタンおよび通知クリックで、設定した新着情報画面へ確実に遷移します。
- 設定画面の「テスト通知を送信」で、desknet's NEOへアクセスせずに端末の通知機能
  そのものが使えるかを確認できます（通知の作成要求が成功したかまでしか判定できず、
  実際にWindowsのバナーへ表示されたかどうかまでは保証できません）。
- Windows側の通知が利用できない端末でも、ツールバーアイコンのバッジとポップアップで
  新着件数を確認できます。

## インストール方法

詳細手順は [docs/installation.md](docs/installation.md) を参照してください。概要は次のとおりです。

1. `chrome://extensions` を開き、「デベロッパー モード」をオンにする。
2. 「パッケージ化されていない拡張機能を読み込む」からこのリポジトリのフォルダを選択する。
3. Chromeでdesknet's NEOに通常どおりログインする（拡張機能にID・パスワードは入力しません）。
4. 拡張機能の設定画面で接続先URLと通知対象トピックを設定する。

## desknet's NEOのURL設定方法

拡張機能の設定画面（ポップアップの「設定」ボタン、または
`chrome://extensions` の拡張機能詳細から「拡張機能のオプション」）を開き、
「接続先」欄にURLを入力します。

> desknet's NEOのトップ画面URLではなく、
> 電子会議室の「新着情報」画面を開いた状態のURLを設定してください。

トップ画面やベースURLだけを登録しても新着情報を取得できません。ブラウザで
電子会議室の新着情報画面を開き、そのときのアドレスバーのURLをコピーして
登録してください。

- `http` または `https` のURLのみ登録できます。
- 前後の空白は自動的に除去されます。
- 不正な形式のURLは保存されません。
- 末尾スラッシュの有無は自動的に正規化されます。
- 保存時に、そのURLのオリジンへのアクセス許可を求めるダイアログが表示されることが
  あります（他のサイトへはアクセスしません）。
- 通知をクリックして開くURLは、登録したdesknet's NEOと同一オリジンであることを
  必ず確認したうえで開きます。

URLはソースコードに固定されておらず、利用者が設定したものだけを使用します。

## 監視対象トピックの設定方法

設定画面の「通知対象トピック」では、「＋ トピックを追加」ボタンで通知対象を
**最大20件**まで自由に追加できます。各トピックのカードには次の項目があります。

- 通知する（ON/OFF）
- トピック名
- トピックURL
- 解析された会議室ID（`fid`）・トピックID（`tid`）の表示（読み取り専用）
- 初回確認状態の表示
- 削除ボタン

**初期状態ではトピックは0件、追加したトピックも初期値は「通知する」がOFFです。**

### トピックURLの登録方法

自組織の電子会議室で対象トピックを開き、ブラウザのアドレスバーに表示されている
URLをそのまま「トピックURL」欄へ貼り付けてください。desknet's NEOはハッシュ
ルーティング（`#cmd=forumalist&fid=8&tid=2319&init=3` のような形式）を使用しており、
このURLから会議室ID（`fid`）とトピックID（`tid`）を自動的に読み取ります。

トピックURLは次を満たす必要があります。

- `http` または `https` の完全なURLであること
- 接続先に設定した新着情報画面と同一オリジンであること
- ハッシュ部分に `cmd=forumalist` と `fid`・`tid` が含まれていること

「トピック名」は表示用のラベルとしてのみ使い、新着照合には使いません
（次項参照）。通知ONの場合はトピック名・URLの両方が必須です。

### トピック名だけでなく内部IDで識別する

新着投稿の判定は、**トピック名ではなく会議室ID（`fid`）とトピックID（`tid`）の
組み合わせを優先**して行います。そのため、後からトピック名を変更しても、URLが
指す会議室・トピックが変わっていなければ同一トピックとして継続検知します。
（`fid`・`tid`を取得できない旧設定に限り、トピック名の完全一致で照合します。）

同じ`fid`・`tid`の組み合わせを複数登録することはできません。ただし、`fid`・`tid`が
異なれば、同じトピック名を複数登録することは可能です。

### 初回確認・変更時の扱い

トピックを新規追加した場合や、登録済みトピックのURLを変更して`fid`・`tid`が
変わった場合は、そのトピックは「初回確認待ち」の状態になります。最初の確認では
その時点に存在する投稿を新しい基準値として登録するだけで、通知は行いません
（名称変更やURL変更をきっかけに過去の投稿が大量通知されることはありません）。
トピック名だけを変更した場合は、初回確認状態は維持されます。
OFFにしていたトピックを新たにONにした場合も、安全のため初回確認からやり直します。

## 旧バージョン（v0.1.x）からの移行

v0.1.xでは通知対象は固定2件・トピック名のみの管理でした。v0.2.0へ更新すると、
初回起動時に自動的に新しい形式へ移行されます。

- 既存のトピック名はそのまま引き継がれます。
- 移行されたトピックにはURLが無いため、**安全のため自動的に「通知する」がOFFへ
  変更されます**。
- 設定画面に「以前の設定を引き継ぎました。通知を再開するには、対象トピックのURLを
  入力してください。」という案内が表示されます。該当トピックのカードにトピックURLを
  入力し、必要に応じて「通知する」をONにしたうえで保存してください。
- 移行処理は複数回実行しても、トピックが重複生成されることはありません。

## 初回確認について

トピックを初めて有効にしたとき（または拡張機能を初めて使うとき）の最初の確認では、
その時点で存在する投稿を「既知の投稿」として登録するだけで、**通知は行いません**。
以降の確認で新しく追加された投稿だけが通知対象になります。

次の場合も「初回確認待ち」の状態に戻り、その時点の投稿を通知せず基準値として
登録し直します。

- トピックURLを変更し、会議室ID（`fid`）またはトピックID（`tid`）が変わった場合
  （別のトピックとして扱われるため）
- OFFにしていたトピックを新たにONにした場合

トピック名だけを変更した場合（`fid`・`tid`が同じ場合）は、初回確認状態は維持され、
やり直しにはなりません。

設定画面には、各トピックについて「初回確認: 完了」「初回確認: 待ち」の表示があります。

## 確認間隔について

- 選択できる間隔は **3分・5分・10分** の3種類です（初期値は5分）。
- `chrome.alarms` を使用しており、**Chromeが起動していない間は確認されません。**
- Chromeのアラームは厳密なリアルタイム実行を保証しないため、
  「数分間隔の確認」であり、投稿から通知までの遅延が生じる場合があります。
- 1分未満の高頻度な監視はできません。

## ログイン切れ時の動作

以下のような状態を検出した場合、**新規投稿として誤って通知することはありません**。

- ログイン画面へのリダイレクト
- 認証エラー・アクセス権限エラー
- セッション切れを示す画面
- 新着情報画面ではない想定外のHTML
- サーバーへ接続できない状態

これらの状態は、ポップアップ内の状態表示とツールバーアイコンのバッジでのみ
知らせます（デスクトップ通知はうるさくなるため、原則として行いません）。
ただし設定で「ログイン切れへ変化した最初の1回だけ通知する」をONにすると、
正常状態からログイン切れへ変化した最初の1回だけデスクトップ通知します
（初期値はOFFです）。

## 使用するChrome権限と理由

権限ごとの理由は [docs/security.md](docs/security.md) に一覧表があります。要約:

- `storage`: 設定・通知済み履歴の保存
- `alarms`: 数分間隔の定期確認
- `notifications`: デスクトップ通知の表示
- `offscreen`: サービスワーカーにDOM APIが無いため、隠しページでHTML解析するため
- `tabs`: 通知クリック時に既存タブを再利用するため
- `optional_host_permissions`: 利用者が設定したdesknet's NEOのオリジンのみへの
  アクセスを実行時に要求するため（Manifest V3の制約上、静的な `host_permissions`
  には利用者が後から入力するURLを事前に書けないため、広いパターンを宣言した上で
  実際にはそのオリジン1件のみを要求します）

## 保存する情報・保存しない情報

詳細は [docs/security.md](docs/security.md) を参照してください。要約:

**保存する情報（すべて `chrome.storage.local` のみ、Chrome同期は使用しません）**

- 接続先URL・確認間隔・通知対象トピック（内部ID・トピック名・トピックURL・
  会議室ID/トピックID・ON/OFF・初回確認状態、最大20件）・通知設定などの設定値
- 通知済み投稿の識別キー（投稿ID、または投稿情報のSHA-256ハッシュ値。本文そのものは保存しません）
- 最終確認日時・前回確認結果・デバッグ用の件数情報

**保存しない情報**

- desknet's NEOのID・パスワード
- Cookie
- 投稿本文の全文
- 職員名を含む恒常的なログ

## 外部通信について

このツールはdesknet's NEO以外のいかなる外部サーバー・外部API・CDNとも通信しません。
外部ライブラリも使用していません。

## 画面変更時の注意

desknet's NEOの画面（HTML構造）が変更された場合、この拡張機能のDOM解析が
正しく動作しなくなる可能性があります。解析処理は `src/desknets/forum-parser.js` と
`src/desknets/authentication-detector.js` に集約しているため、画面変更時は
この2ファイルを中心に調整してください。調査結果は
[docs/desknets-v6-dom-investigation.md](docs/desknets-v6-dom-investigation.md) に記録します。

## トラブルシューティング

| 症状 | 確認事項・対処 |
| --- | --- |
| ポップアップが「未設定」のまま | 設定画面で接続先URLを登録し、保存してください。 |
| 「desknet's NEOへのログインが必要です」と表示される | ブラウザでdesknet's NEOに再ログインしてください。 |
| 「接続できません」と表示される | ネットワーク接続、URLの誤り、社内ネットワーク（VPN等）への接続状況を確認してください。「接続確認」ボタンで再試行できます。 |
| 「画面構造を認識できません」と表示される | desknet's NEOの画面が変更された可能性があります。開発者に連絡し、実画面のHTMLを確認してもらってください。 |
| 通知が来ない | 対象トピックがONになっているか、デスクトップ通知が有効か、Chrome自体の通知設定（OS側含む）を確認してください。初回確認直後は既存投稿が通知されない仕様です。設定画面の「テスト通知を送信」で、そもそも端末の通知表示自体が機能しているかを切り分けられます。 |
| 「認識した投稿件数」が常に0件のまま | 接続先URLがトップ画面など「新着情報」画面以外を指していないか確認してください。設定画面の「詳細情報（デバッグ用）」で、トピックリンク検出件数・投稿行候補件数を確認できます。 |
| 対象トピックの投稿があるのに「対象一致」が0件のまま | トピック名の表記が完全に一致しているか確認してください（前後の空白以外は自動調整されません）。「詳細情報」の「設定トピック名がHTML内に存在」が「なし」の場合は、名称の設定ミスの可能性が高いです。 |
| 同じ投稿が何度も通知される | 「今すぐ確認」を複数回押していないか、設定画面から通知済み履歴をリセットしていないかを確認してください。 |
| 「電子会議室を開く」を押しても新着情報画面に切り替わらない | 拡張機能を最新版に更新してください（既存タブを前面表示するだけで遷移しない不具合は修正済みです）。 |

## アンインストール方法

`chrome://extensions` の拡張機能詳細から「削除」を選択してください。保存されていた
設定・通知済み履歴もあわせて削除されます。

## 制限事項

- 新着情報画面は「投稿単位」ではなく「トピックの最新状態」を表示する方式のようです。
  そのため、**同一トピックへ短時間に複数投稿された場合、途中の投稿を個別に検知できず、
  最後の投稿しか通知されない可能性があります**。
- ログイン切れ・エラー画面そのものは実機未確認のため、その判定はヒューリスティック
  （推測に基づく複数条件判定）であり、実際のdesknet's NEOのエラー画面と一致しない
  可能性があります（詳細は
  [docs/desknets-v6-dom-investigation.md](docs/desknets-v6-dom-investigation.md)）。
- Chromeが起動していない間、および休止状態のサービスワーカーが再起動されるまでの間は
  確認が行われません。
- 確認は数分間隔の目安であり、投稿から通知までのリアルタイム性は保証されません。
- 新着情報画面をGETで取得すること自体がdesknet's NEO側で既読扱いになるかどうかは
  未検証です（詳細は同上ドキュメント）。
- 新着情報画面から取得できる件数（1ページに表示される件数）を超えて遡って
  投稿を検知することはできません。
- desknet's NEOのカスタマイズや将来のバージョンアップでCSSクラス名・DOM構造が
  変更された場合、専用パーサーが対象を認識できなくなる可能性があります。
- `http` 環境（庁内ネットワークなど）でもChrome拡張の通知APIは利用できますが、
  端末やOSの通知ポリシーによっては、通知の作成要求自体は成功しても実際には
  表示されない場合があります。「テスト通知を送信」はあくまで通知作成要求の
  成否までしか確認できません。
- 「現在開いているタブから対象トピックの情報を自動取得する」機能は今回のバージョン
  では実装していません。トピック名・トピックURLは利用者が手動で入力する方式です。

## 開発者向け情報

### ディレクトリ構成

```text
desknets_noticer/
├─ manifest.json
├─ src/
│  ├─ background/        バックグラウンド処理（アラーム・通知・全体制御）
│  ├─ desknets/          desknet's NEOとの通信・DOM解析・認証状態判定
│  ├─ storage/           設定・通知済み履歴・実行時状態の永続化
│  ├─ popup/             ツールバーのポップアップUI
│  ├─ options/           設定画面UI
│  ├─ offscreen/         DOM解析専用のオフスクリーンドキュメント
│  └─ shared/            定数・データモデル・テキスト整形ユーティリティ
├─ tests/                解析処理などのテスト（Node.js + jsdom）
├─ docs/                 調査メモ・インストール手順・セキュリティ方針
└─ icons/                独自作成のアイコン
```

### テストの実行方法

拡張機能本体はビルド不要ですが、テストの実行にはNode.jsが必要です
（`jsdom` を開発依存としてのみ使用しています）。

```sh
npm install
npm test
```

### デバッグ機能

設定画面の「詳細情報（デバッグ用）」から、最終取得日時・取得結果種別・
トピックリンク検出件数・投稿行候補件数・認識した投稿件数・対象トピック一致件数・
新規判定件数・使用した解析方式・設定トピック名がHTML内に存在したか・エラーコードを
確認できます。投稿本文・職員名・Cookie・認証情報はここには表示されません。

トピックリンクを1件も検出できなかった場合（新着が本当に0件の場合を含む）は、
状態は「正常」のまま維持されますが、エラーコードに`NO_TOPIC_LINKS_FOUND`が
記録されるため、実際に新着が無いのか、画面変更でパーサーが対象を認識できて
いないのかを切り分けられます。
