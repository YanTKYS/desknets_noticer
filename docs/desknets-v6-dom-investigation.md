# desknet's NEO v6.0 R1.0 画面構造調査メモ

このドキュメントは、desknet's NEO v6.0 R1.0の「電子会議室」新着情報画面のHTML構造を
調査した結果を記録するためのものです。

**重要な注記**: 本実装の時点では、実際のdesknet's NEO v6.0 R1.0の画面（または保存HTML）を
確認できていません。以下、確認できた項目には「確認済み」、確認できていない項目には
明確に「未確認」と記載します。未確認の項目を確認済みであるかのように記載することはしません。

実画面のHTMLが提供され次第、このドキュメントと `src/desknets/forum-parser.js` /
`src/desknets/authentication-detector.js` のセレクターを更新してください。

## 新着情報取得による既読状態への影響

- 未確認。新着情報画面をGETで取得するだけで投稿が既読になる仕様かどうかは、
  実機で検証する必要があります。
- 本実装ではGETリクエストのみを行い、POST・更新・削除・既読化API等は一切呼び出して
  いません。ただし、desknet's NEO側の実装によっては、新着情報画面の閲覧自体が

  画面を開いたときと同じ影響が生じます（拡張機能が既読状態を追加で変更することは
  ありません）。

## 会議室名の取得方法

- 未確認（実画面ベースでは）。
- 暫定実装: `data-room-name` 属性 → `.room-name` 等のクラス名 → 「会議室:」ラベル
  文字列、の優先順位で取得する（`src/desknets/forum-parser.js`）。

## トピック名の取得方法

- 未確認（実画面ベースでは）。
- 暫定実装: `data-topic-name` 属性 → `.topic-name` 等のクラス名 → 「トピック:」
  ラベル文字列、の優先順位で取得する。トピック名は完全一致で対象を判定する。

## 投稿IDの有無

- 未確認。
- 取得できる場合は `data-post-id` 属性、またはリンクURLのクエリパラメーター
  （`post_no` / `postid` / `post_id` / `res_no` 等、実画面で要確認）から抽出する
  暫定実装としています。

## 投稿者名の取得方法

- 未確認（実画面ベースでは）。
- 暫定実装: `data-author` 属性 → `.author` 等のクラス名 → 「投稿者:」ラベル文字列。

## 投稿日時の取得方法

- 未確認（実画面ベースでは）。
- 暫定実装: `data-posted-at` 属性 → `time[datetime]` 要素 → `.posted-at` 等の
  クラス名 → 「投稿日時:」ラベル文字列。

## 本文の取得方法

- 未確認（実画面ベースでは）。
- 暫定実装: `data-body-preview` 属性 → `.body-preview` 等のクラス名 →
  「本文冒頭:」ラベル文字列。スクリプト・スタイル要素は除去してからテキストを
  取得する。

## 対象URLの取得方法

- 未確認（実画面ベースでは）。
- 暫定実装: 行内の最初のリンク（`a[href]`、`cabinet`/`bbs`/`forum`/`topic`/`post`を
  含むhrefを優先）を投稿URLとして採用する。

## 採用したDOMセレクター

`src/desknets/forum-parser.js` の `ROW_SELECTOR_STRATEGIES` に以下の優先順位で
定義している（詳細はコード参照）。

1. `[data-post-id], [data-topic-post-id], [data-forum-post]`（識別子ベース）
2. `[data-room-name][data-topic-name], [data-room-id][data-topic-id]`（data-*属性）
3. `#newArrivalList li, #newArrivalList tr, ...`（ラベル文字列・相対DOM構造）
4. `table.newArrivals tr, ul.newArrivals li, ...`（CSSクラス名、最終手段）

## セレクターの安定性評価

- 上記のセレクターはすべて、実画面ではなく一般的な業務グループウェアの
  新着情報一覧を想定した**仮の設計**です。安定性の評価は実画面確認後に
  記載します。
- 現時点で確度が高いと言えるのは「識別子ベース（1）」「data-*属性（2）」の
  優先順位そのものであり、実際の属性名・クラス名は未確認です。

## 将来の画面変更時に確認すべき箇所

- desknet's NEOのバージョンアップやカスタマイズにより新着情報画面のHTML構造が
  変わった場合は、以下を確認してください。
  1. 新着情報一覧のコンテナ要素（idまたはクラス名）
  2. 1件分の投稿を表す行要素（`li`/`tr`など）の構造
  3. 会議室名・トピック名・投稿者名・投稿日時・本文冒頭の取得元（属性名／クラス名／
     ラベル文字列）
  4. 投稿URLのクエリパラメーター名（`post_no`など）
  5. ログイン切れ・エラー画面のHTML構造（`src/desknets/authentication-detector.js`）
- 変更が必要な場合は、`src/desknets/forum-parser.js` と
  `src/desknets/authentication-detector.js` の2ファイルのみを修正すれば
  対応できるように設計している。
- `tests/fixtures/` に実画面から個人情報を除去したHTMLを追加し、
  `tests/forum-parser.test.js` で解析結果を検証すること。
